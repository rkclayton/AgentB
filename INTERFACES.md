# Agent_b interfaces

This document is the stable runtime contract. Bracketed prompt numbers are historical provenance only and carry no sequencing authority.

## Event envelope and transport

Every durable domain event is `{"seq":int,"ts":"RFC3339 with milliseconds","session_id":"","run_id":"","type":"","data":{}}`. Sessionless events are global. JSONL additionally permits `body` on `model.request` and `raw` on `model.response`; those fields are excluded from transport. Each session has its own log and global events use the Agent_b log. SSE sends top-level global events in that envelope, but session updates are `projection.patch` envelopes rather than raw domain events. A comment ping is sent every 15 seconds.

On SSE connection, `snapshot` [prompt 3] contains `{sessions:{<id>:SessionSnapshot},servers:[Profile with masked key],config,agent_server_changes:{<agent_id>:{agent_id,from,to,requested_at}},replay,build:{tag,commit,dirty,known,source,display,executable_sha256},signature,mutation_token,shell_credential:{stored,stored_at},shell_identity:{fallback,operator_approval_required,operator_context,operator_context_expires_at,reason,since},serving_facts,flow:{stages,edges},tools:[{name,description}]}`. `agent_server_changes` contains only queued, not-yet-applied binding changes. `build` identifies the running binary; the shared headers render `tag`, the first seven commit characters, dirty state, and the adjacent signature state. Dirty builds append `+dirty` to the display value, and `executable_sha256` is the hash the signing helper must match before replacement. `signature` is the latest Settings verification result. `mutation_token` is a per-launch browser/CSRF secret required in `X-AgentB-Mutation-Token` on every non-read request; it is not persisted or logged. `replay` is true only for `-replay` servers. The credential status never contains the credential.

## Shared records

`SessionSnapshot` schema 1 is `{schema_version:1,cursor:{generation,offset},complete,projection_stale?,projection_stale_reason?,id,label,server_id,agent_name,main_profile,created_at,closed,workspace,run:{status:idle|queued|running|paused|stopping,run_id,turn,max_turns,queue_position,partial,last_stop_reason},activity,tools:[{name,enabled,calls,schema_tokens,marginal_tokens}],messages:[Message],budget:Budget,timeline:[durable operational events plus only the current model stream],chat:[server-projected ChatEntry with agent_role:main|aux when applicable],pending_approval?:ChatEntry,queued_messages,runnable,not_runnable_reason,memory_path,memory_content,log_path,model_turns,compaction_count,compaction_token_delta,compaction_model_calls,compaction_prompt_tokens,compaction_completion_tokens}`. `last_stop_reason` distinguishes `aborted_mid_model`, `aborted_mid_tool`, and `aborted_mid_run` from `done`. `complete:false` means the generation lacks a reachable `session.created` seed, so absent values are not represented as guessed defaults. Replay is a transport/UI overlay and never rewrites historical `run.status`. Aggregate fields, Activity, History, and Chat are folded by the one pure server projector from JSONL; clients do not independently derive them from event types. Chat coalesces repeated `model_unreachable` stops for the same host into one condition entry until `model.reachable` sets that entry's `decision:"resolved"`; Timeline retains every underlying stop event. Completed `model.delta` and `model.progress` records remain in JSONL but leave the projected timeline once their response arrives, so token traffic cannot evict operational history. Compaction prompt/completion totals remain a separate inference-spend ledger. `memory_content` is the read-only injected view for Settings; `log_path` names the current generation. Tool token fields and memory fields remain zero/empty until accounting runs. `schema_tokens` is isolated rendered schema size; `marginal_tokens` is the current request-prefix saving from disabling that enabled tool, including its system-prompt name. The compacted-history archive is absent from model-visible `messages`; live lookup remains a session-scoped index of immutable JSONL record locations, and replay rebuilds the same non-model archive separately from the session snapshot. Session events are also appended to `chats/{id}.jsonl` under the operator data root. That retained journal rehydrates the chat and transcript into a fresh operational log generation at startup; log rotation and retention never remove it. On the first upgraded launch only, an empty retained store is seeded from the newest pre-v0.44 operational generation for each recorded session ID.

Schema 1 additive workspace fields are `workspace_dir` (the canonical bound directory; legacy `workspace` remains an alias), `workspace_missing`, `project_content`, `project_files`, `project_notes`, `pending_repo_policy?`, and `repo_policy?`. The `project` budget category sits between `system` and `memory`. `session.created` seeds all of these so JSONL replay reconstructs the same binding, instructions, and policy card.

The versioned durable projection is session-scoped only. Top-level snapshot state (`servers`, masked `config`, build identity, shell identity and credential status, serving facts, flow, and static tool inventory) remains assembled by its existing runtime owners; the global JSONL has no startup seed from which those fields could be reconstructed. A projection cache is keyed by projection schema, log generation, and durable byte offset, is never persisted, and is always discardable rather than authoritative. A snapshot request projects through a captured complete-record boundary; later successful appends are applied once in memory. `projection.patch` is `{schema_version:1,session_id,previous_cursor,cursor,operations:[{op:replace|append|upsert|delete,path,value?}]}`. A cursor mismatch causes a full snapshot resync. The SSE subscription and captured cut are atomic, so a record cannot appear in both the snapshot and the post-cut patch stream. A full queue is closed rather than dropping a patch, forcing EventSource resynchronization. This boundary does not add a global seed event.

`Message` is `{id,role:system|user|assistant|tool,content,reasoning?,tool_calls?,tool_call_id?,name?,category:system|memory|tools|history|files|results|fetched|summary,tokens,estimated,elided,turn,ok?}`. A compaction message uses `role:assistant,category:summary`: the endpoint receives its complete content as harness context, while Chat projects a visibly labelled summary entry and omits its prompt-only prefix and compaction-evidence appendix. `ok` is present on newly recorded tool messages so a snapshot or replay does not have to infer outcome from prose; older recordings may omit it. `fetched` content carries an unmistakable untrusted-data envelope in the model-visible text. Successful jailed `write_file` and `edit_file` tool results additionally carry `file:{path,bytes}` in their projected result metadata. The path is normalized relative to that session's workspace. Shell and `run_script` filesystem effects do not carry this metadata because their child-process writes are not observed by tool identity.

`Budget` is `{n_ctx,reserve,ceiling,used_est,used_measured,drift,cached_last:null|int,mode:exact|estimated,estimated,estimated_categories:[...],categories:{system,memory,tools,history,files,results,fetched,summary},tool_schema_tokens:{name:int},tool_marginal_tokens:{name:int}}`. `categories.tools` is the actual combined enabled-tools block. Neither per-tool map is additive because the rendered tool template has shared scaffolding; marginal values also cross the `system`/`tools` category boundary by including each tool's name-list contribution.

`Config.roles` has `{main,aux}` profile IDs. During first run, `servers:[]` is valid only with both roles empty; this state has no startup session and routes normal live pages to `/setup`. Once any profile exists, `main` must name a profile; `aux` may be empty and then resolves silently to `main`, and the same profile may fill both roles. `run.max_turns` is a pathological-case backstop whose shipped default is 10000; it is not shown as an ordinary Settings control. An explicit zero is rejected as ambiguous rather than silently becoming the default. `Profile` has `{id,label,base_url,model,credential,request_timeout_s,probe_mode,attachment_handling:auto|native|extract,sampling:{thinking,nonthinking},reasoning:{control,enabled,effort,valid_efforts,preserve},context:{n_ctx,reserve_output},system_prompt_override,capabilities}`. Omitted `attachment_handling` defaults to `auto`: `auto` follows probed document/image capability, `native` sends supported attachment kinds regardless of the probe, and `extract` keeps their binary bytes out of the model request. `context.n_ctx` is the required authoritative context size for that profile; probed `capabilities.n_ctx` is evidence and initializes it only while unset. Parameters remain properties of profiles, not roles. A submitted `api_key` is runtime/API input only: it is stored under the named user-scoped DPAPI `credential`, appears as `"•••• set"` in masked API/event output, never enters logs, and is omitted from `harness.json`.

`Capabilities` has `{server:llama.cpp|openai-compatible|unknown,props,n_ctx,tokenize,apply_template,apply_template_tools,streaming,tool_calls,grammar_constrained,cached_tokens,timings,prompt_progress,reasoning_control:chat_template_kwargs|top_level|server_flag|none,reasoning_emission?:structured|inline|none,valid_efforts,overflow_behavior:error|truncate|unknown,probed_at,findings}`. `reasoning_emission` is absent until a full controlled reasoning probe classifies it.

## Model-server transport

Profiles target an OpenAI-compatible server at `base_url`. Generation uses `POST /v1/chat/completions`; a nonempty profile key is sent as `Authorization: Bearer <key>`. All requests use JSON and the profile's request timeout. Standard sampling, messages, tools, tool choice, streaming, and usage fields are always OpenAI-shaped. `top_k`, `min_p`, `repeat_penalty`, `cache_prompt`, `return_progress`, and `chat_template_kwargs` are sent only when the probed server is llama.cpp. Reasoning controls never send an effort outside the profile's probed `valid_efforts`. Streaming tool-call arguments may arrive whole or as indexed fragments and are accumulated by index.

Agent-loop `max_tokens` is `min(max(4096, profile.context.reserve_output), n_ctx - guarded prompt tokens)`, where 4096 is the non-configurable plausible-tool-call floor; estimated accounting applies its 10% prompt guard before this calculation. Before dispatch, output headroom below that floor independently invokes the existing elide/summarize compactor. If compaction still cannot provide the floor, the run stops with `context_ceiling` and sends no knowingly truncated request. A response ending with `finish_reason:length` while emitting tool arguments never becomes a model-visible tool call or result. The original turn is retried once with that function forced, without adding a user message or other model-visible continuation; `model.retry` makes the harness action visible. A second truncation, a retry that does not return the forced call, or a prose response ending at the limit stops honestly with reason `length`. If `/apply-template` rejects existing history, its non-200 response body is included in the durable operational error; the runner removes the newest locally malformed assistant tool-call structure and paired results, retains its prose and later messages, emits `model.retry`, and retries accounting once. It never degrades a template failure to estimated accounting.

The 2.5-second availability fast-fail applies only while establishing a connection. Once connected, tokenization and template accounting use the profile's normal request timeout. A connected transport failure during accounting degrades that measurement to estimated counts, including the 10% prompt guard, and does not stop or suppress compaction; the next measurement attempts exact accounting again. A dial failure retains the existing `model.unreachable` classification because the generation endpoint is unavailable too.

A generation request carries model-visible tools or a structured-output schema, never both. The current transport has no structured-output field: agent-loop and reliability-probe requests may carry tools, while compaction and all other probe requests carry neither.

Capability probing uses `GET /props` (falling back to `GET /v1/models`), `POST /tokenize`, `POST /apply-template`, and bounded chat-completion checks. A transport failure retains prior capabilities and leaves `probed_at` unchanged. `probe_mode:off` uses documented assumptions, `minimal` performs only the inexpensive identity/tokenization/template/streaming checks, and `full` includes tool, reasoning, timing, cache, progress, and overflow behavior. The controlled reasoning request classifies emission as structured, inline, or none; an inline finding names the server-side reasoning-format fix. Every assumed or measured result produces a plain-language finding.

## Model-visible tool interface

The registry sends enabled tools in this stable order: `read_file`, `list_dir`, `write_file`, `edit_file`, `search_text`, `shell`, `remember`, `recall`, `fetch_url`, `find_files`, `run_script`, `call_service`. The internal-service caller is position 12; all earlier positions remain stable. Tool errors normally enter model context with an `error:` prefix and always produce `tool.result.ok:false`; a stale-view or routing refusal may instead start with `note:` while remaining an unsuccessful, unexecuted outcome. Documented empty/no-match results are successful outcomes.

- `read_file {path,offset?,limit?}` reads numbered UTF-8 source text using a one-based byte offset and byte budget. Its header reports `offset`, source `bytes`, `total`, `more`, optional `next_offset`, `start_line`, `start_mid_line`, and `end_mid_line`; display line prefixes are outside the byte budget. When `more` is true the returned `next_offset` is passed back as `offset`. If the requested successful window would exceed the current model-context result budget, the harness repeats this read internally and returns the largest successful window that fits, prefixed by an explicit context-clamp line naming requested/returned/remaining bytes and the continuation offset. The model receives one successful tool result rather than a failed retry turn.
- `list_dir {path?,depth?}` enumerates a directory with directories first, case-insensitive alphabetical order, two-space nesting, configured ignored directories, depth 1 by default and 3 maximum, and a configured result cap. Inaccessible descendants are skipped and counted instead of aborting the enumeration. Directories end in `/`; an empty result is `directory is empty`.
- `write_file {path,content}` atomically creates or replaces a file, creates parent directories, and refuses content over 512 KiB. A successful result reports the path and written line count.
- `edit_file {path,old_string,new_string}` requires one unique match, preserves UTF-8 BOM and CRLF style, and atomically replaces or deletes it. Exact matching is attempted before indentation-aware whitespace matching; ambiguous or absent matches are errors with line-oriented diagnostics. Success reports affected lines and a numbered context region.
- `search_text {pattern,path?,glob?}` recursively applies a regular expression to text, optionally filters by basename glob, skips configured ignored directories, inaccessible descendants, inaccessible files, and NUL-detected binary files, and returns `path:line: text`. Skipped inaccessible entries are counted. Results use the configured match count and per-line rune caps; no matches is a successful `no matches` result.
- `shell {command,timeout_s?}` starts an unconfined command in the workspace directory with bounded combined stdout/stderr. Its model-facing description names the syntax derived from `shell.command[0]`. The service-context network restriction is enforced outside the tool layer; network operations belong in `fetch_url`. The agent-written-file provenance rule is limited to Windows script hosts (`powershell`/`pwsh`, `cmd`, `wscript`, `cscript`, `mshta` and their host-executable suffixes); Python, Node, Go, .NET, and other interpreters are not blocked by that rule. Execution-policy bypass remains forbidden. `Set-AuthenticodeSignature`, `signtool`, and certificate-store mutations via `certutil` are reserved for Settings under either identity. A nonzero exit is an error containing `exit=<code>` and nonempty combined output. Simple file discovery/read commands return a structured unsuccessful routing refusal naming the first-class replacement tool, and the command is not executed. With the service split enabled, an out-of-workspace discovery path instead reports the operator-decision boundary and supplies no replacement call.
- `remember {note}` appends a trimmed workspace note of at most 300 Unicode runes; an exact duplicate is a successful no-op and a new note becomes active next session. `recall {}` returns all notes for the active workspace or a successful empty-state message. Neither accepts a path and neither is widened by operator mode.
- `fetch_url {url,offset?,limit?}` performs a policy-checked public HTTP(S) GET with no model-supplied headers, cookies, or credentials and returns untrusted text in a UTF-8-safe byte window. When `allow_domains` is empty, `deny_domains` refuses listed hosts and subdomains before DNS or request dispatch; a nonempty `allow_domains` remains authoritative and supersedes that default deny list. The result and event metadata report URL/status/source and window fields. When `more` is true the returned `next_offset` is passed back as `offset`.
- `find_files {pattern,path?}` recursively matches filenames or relative paths, supports `**`, skips its fixed ignored directories, configured protected roots, and inaccessible descendants, reports the inaccessible count, sorts results, and returns at most 200 paths with an explicit truncation marker; no matches is a successful `no matches` result.
- `run_script {language:powershell|python|node,source,timeout_s?}` sends source over stdin without creating or executing a script file. PowerShell is invoked exactly as `-NoProfile -NonInteractive -Command -`; `-File` and `-EncodedCommand` are never used. It shares shell's identity, split-mode confirmation, configured approval policy, timeout/output limits, working directory, process-tree handling, and once-approved operator override. Full source remains in `tool.call` arguments and assistant tool-call history in JSONL/replay.
- `call_service {service,method,path,query?,body?,headers?,offset?,limit?}` resolves a named internal service from the configured empty-by-default allowlist. The path must be relative and remain under that service's `base_url`; redirects are checked against the same root. The method must be configured, and model headers are limited to `Accept`, `Content-Type`, `If-Match`, `If-None-Match`, and `Idempotency-Key`; `Authorization` is always tool-owned. Auth is `none`, `static_bearer:<env>`, or `exec:<argv>`. Exec argv runs directly as the non-elevated operator without a shell and is cached until 60 seconds before RFC3339 `expires_at`, or for five minutes when expiry is absent. The result is `{status,headers,body,cursor,duration_ms}`; 4xx/5xx remain successful results, response headers are a fixed subset, and `max_body_kb` caps each one-based byte window. Continuing with `next_offset` repeats the configured request. Authorization values and bearer tokens never enter durable events, History, flow, or returned content. `require_confirmation:true` is parsed and logged but intentionally has no effect in this release. This identity-bearing internal-service surface remains distinct from anonymous, GET-only, untrusted-open-web `fetch_url`.

## Events

- `session.created` [prompt 3] `{session}`; `session.renamed` [3] `{session_id,label}`; `session.updated` `{session_id,server_id,agent_name,main_profile,runnable,not_runnable_reason,memory_path,memory_content}`; `session.reset` [3] `{session_id,log_path,predecessor?:{generation,offset}}`; `session.closed` [3] `{session_id}`; `session.reopened` `{session_id}`. Closing refuses any active/queued/paused/stopping run and hides the tab without deleting, resetting, or stopping anything; reopening restores that retained chat to the tab strip. Closed sessions stay in projected state so the right-click history can list and reopen them. New reset generations identify the exact complete-record boundary of their predecessor. Historical reset generations without this field remain honestly incomplete and do not receive invented lineage.
- `server.probed` [3] `{server_id,capabilities,findings}`; `config.changed` [3] `{config,notice?}` (masked; `notice` is emitted for a one-time config migration); `error` [3] `{where,message,lost_event_type?}`. `where:event_log` means the named event could not be persisted to JSONL and the error itself exists only in live state.
- `agent.server_change` is sessionless runtime state. Pending is `{status:"pending",change:{agent_id,from,to,requested_at}}`; applied and cancelled are `{status:"applied"|"cancelled",agent_id,from,to}`. It is live transport state rather than a durable session projection event.
- `navigation.started` records every initiated Chat/Console flip or settings-cog transition as `{navigation_id,navigation_kind:flip|settings,from,to,full_document,clicked_at,chat_id,since_previous_navigation_ms:null|number,subscriber_count}`. `subscriber_count` is read from the server's live `events.Bus` registry when the start reaches the server; it is not a page-local estimate. The event is written independently of completion so an abandoned navigation remains visible. Chat/Console flips set `full_document:false`, update history, and mount the selected resident view without assigning a new document. A full-document navigation elsewhere still synchronously claims the current document before assignment; any later click from that document is ignored and recorded as `navigation.suppressed`. `navigation.measured` records one completed transition as `{navigation_id,navigation_kind:flip|settings,from,to,document_request_parse_ms,module_page_init_ms,session_state_fetch_ms,event_stream_connect_ms,transcript_surface_rebuild_paint_ms,end_to_end_ms,transcript_entries,chat_id,model_reachability:reachable|unreachable|unknown,since_previous_navigation_ms:null|number,instrumentation_sync_ms}`. Full-document phase boundaries use the browser Navigation Timing, Fetch, EventSource, projected-snapshot, explicit surface-ready, and second-animation-frame boundaries established by the navigation harness. A same-document flip or settings transition records exact zeroes for the four load operations that do not occur. Both events are projection-neutral and advance only the session cursor.
- Full-document navigation carries the browser-generated `navigation_id` in the target query solely as a correlation key. `navigation.document_started` records `{request_id,navigation_id,path,arrival_at,handler_entered_at,connection_identity}` before the page handler does work; `navigation.document_completed` records `{request_id,navigation_id,path,handler_exited_at,bytes_written,connection_identity}` when it returns. `connection_identity` is Go's observed remote TCP address. Direct document requests without a browser ID receive a server request ID and an empty `navigation_id`. Both events are instrumentation-only and projection-neutral.
- `shell.identity` [17] `{fallback,operator_approval_required,operator_context,operator_context_expires_at,reason,since}` announces or clears a persistent alternate-identity failure and reports process-global operator context. While enabled, `operator_context_expires_at` is the current idle deadline, reset at ordinary tool-execution start and completion. New events set `fallback:false`; failed service spawning requires an operator approval instead of executing automatically. `shell.credential` [17] `{stored,stored_at}` reports write-only store status. `operator.context` [19] `{enabled,reason,expires_at}` audits every transition and idle reset globally and in each live session.
- `signing.applied` records `{thumbprint,signer,timestamp_url,timestamp,files,applied_at}` globally and in every live session after the signed restart consumes its one-time handoff record.
- `run.queued` [4] `{run_id,position}`; `run.started` [4] `{run_id,user_message_id}`; `run.stopping` `{reason}`; `run.stopped` [4] `{run_id,reason,detail,turns}`. Active-stop reasons are `aborted_mid_model`, `aborted_mid_tool`, or `aborted_mid_run`; a queued run stopped before dispatch reports `done`. Cancellation gets 2 seconds to yield, then the scheduler terminates the run, fences its late completion, and returns the session to use. Other reasons are `done`, `mailbox_stop`, `turn_ceiling`, `cycle`, `tool_errors`, `context_ceiling`, `length`, `model_error`, `model_unreachable`, and `profile_not_runnable`.
- `run.aborted` `{reason,detail,turn,stage,tool_in_flight:{name,arguments},partial_output:{reasoning,content,tool_calls:[{index,name,arguments}],tool_result},possibly_written_paths,paths_complete,unverified}` is written before the stopped run becomes resumable. Arguments and partial output are verbatim. A paired system-role `[HARNESS ABORT RECORD]` remains in ordinary history and therefore ages out normally through compaction; request assembly moves that byte-identical harness-authored message into the contiguous leading system block rather than emitting it after conversation history. Possibly partial paths remain explicitly unverified; shell/script paths are reported as unknowable rather than guessed. An event-log append failure emits the existing live `error where:event_log` signal with `lost_event_type` and never fails silently.
- `stage` [4] `{stage,state:enter|exit,turn,ms}`. Stages are `assemble`, `call_model`, `parse`, `dispatch`, `execute`, `append`, `compact`, `wait_user`; compact is initially a no-op.
- `model.request` [4] `{turn,message_count,tool_count,params:{temperature,top_p,top_k?,min_p?,presence_penalty,repeat_penalty?,max_tokens,reasoning:{control,effort?,enabled?,preserve?}},est_prompt_tokens,estimated}`.
- `model.progress` [4] `{turn,total,cache,processed}`; `model.delta` [4] `{turn,kind:reasoning|content|tool_call,index,text}`. Tool-call argument fragments use an empty durable `text`; the complete sanitized arguments arrive on `model.response` and `tool.call`, preventing header values from leaking through incremental JSONL.
- `model.response` [4] `{turn,finish_reason,content,reasoning_tokens,reasoning_tokens_estimated,tool_calls:[{id,name,arguments}],usage:{prompt_tokens,completion_tokens,cached_tokens:null|int},timings:null|object,duration_ms}`.
- `model.retry` `{turn,next_turn?,reason:truncated_tool_call|malformed_tool_history,tool,attempt,max_attempts}` is a visible harness-authored event. It never creates a user-role message or other mid-run prompt injection.
- `tool.call` [4] `{turn,call_id,name,args}`; `tool.result` [4] `{turn,call_id,name,ok,operator_context,untrusted,ms,bytes,tokens,preview,...tool_metadata}`; `tool.toggled` [4] `{name,enabled}`. `operator_context:true` marks a shell/file call that executed with the Agent_b operator identity or a `call_service` call whose `exec:` credential derives from that identity. A nonzero shell exit produces `ok:false`; its model-visible result begins with `error:`, includes `exit=<code>`, and retains nonempty combined stdout/stderr. Fetch metadata is `{url,final_url?,status,source_bytes,source_truncated,content_type?,window_offset,window_bytes,total_bytes,more,next_offset?}` and `untrusted:true`; `call_service` metadata is `{service,method,path,status,duration_ms,window_offset,window_bytes,more,next_offset?}`. The timeline labels both visibly without exposing service auth.
- `message.appended` [4] `{message}`; a user message may carry `attachments:[{path,bytes,sha256,outcome?}]`, while its `content` remains exactly the text the operator typed. `outcome` is harness-generated descriptive status for a native attachment that was not sent because its encoded upper bound did not fit the profile context budget; Chat renders it beside that attachment and the model-visible attachment line carries the same status. `message.updated` [8] `{id,patch}`; `message.removed` `{id,reason:unrenderable_tool_call|operator_repair}`; `message.queued` [6] `{message_id,position}`. Removal is durable projection input used by targeted automatic recovery and the explicit operator repair control.
- `budget` [4] uses the `Budget` shape. Prompt 4 emits a rough estimate; prompt 8 resolves exact versus estimated accounting.
- `approval.required` [6] `{call_id,name,args,boundary_escape}`; `approval.decided` [6] `{call_id,decision:approve|once|run|session|operator_mode|deny|superseded|dismissed}`. At most one decision is pending per session; a newer decision durably supersedes the prior one and cancellation durably dismisses it. `shell.grant` / `shell.grant_lapsed` are `{run_id,scope:run|session,rule:shell_policy|shell_boundary|operator_command,identity:service|operator,executable?,reason?}`; `file.grant` / `file.grant_lapsed` are `{run_id,scope:run|session,identity:operator,reason?}`. Run grants lapse at run end and session grants lapse on `session.closed`; neither scope is global, shell grants never cover file tools, and file grants never cover shell. `cycle.detected` [6] is `{call_id,name,args,prior_call_id}`; `workspace.conflict` [6] is `{path,session_id,other_session_id,other_label,age_s}`. `boundary_escape:false` marks normal approval policy; `true` marks a mandatory dispatcher-only `<tool>.operator_override` or `shell.operator_command` decision.
- `chat.exported` `{path}` records the successful close-time Markdown export. The session ID remains in the event envelope; the path is operator-owned output under `chats/<directory-key>/<date>-<name>.md`, and JSONL remains the durable event authority.
- `compaction.summary` [8] records every summary fit decision or dispatched call as `{role:main|aux,profile_id,model,outcome:accepted|rejected|skipped|error,reason?,fallback_reason?,dispatched,estimated_prompt_tokens,estimated,n_ctx,usage:{prompt_tokens,completion_tokens,cached_tokens},duration_ms}`. A configured distinct aux profile is template/tokenizer fit-checked before dispatch; estimated checks carry a 10% guard. Aux fit, call, or reduction-guard failure falls back sequentially to the session's main profile. Summary requests contain non-elided history/summary prose, assistant working notes, and the currently retained `files`/`results`/`fetched` bodies, plus compact tool evidence with sanitized call arguments, success state, and read/fetch window metadata. Elided bodies are never restored. Accepted summaries carry forward a bounded code-generated appendix of up to 12 evenly sampled, JSON-encoded, 320-rune verbatim tool-result excerpts so early, middle, and late ground truth survives recursive compaction without restoring full discarded bodies. The instruction requires compactly preserving observed findings (including regional anchors for sequential reads), cursor, consumed scope, and stopping condition, treats a referenced name as no proof of its declaration, and forbids invented observations or claims from elided results. `compaction` [8] remains the successful context mutation event `{kind:elide|summarize,before,after,affected_ids,summary_message_id?,role?,profile_id?,model?,fallback_reason?,usage?}`. Elision has no serving profile or model usage. `memory.noted` [8] is `{note,path}`.

## HTTP API

- `GET /` and `/chat` serve the same workspace document, initially mounting Console and Chat respectively; the agent-tab switch mounts the other resident view in place. Settings remains a same-window Console view; `GET /static/*` serves `web/`.
- `GET /api/events` is snapshot-plus-projection-patch SSE; `GET /api/state` is `snapshot.data`. In replay mode each SSE connection receives the initial projected snapshot followed by timestamp-ordered projection patches at 20 ms per durable record; `?instant=1` removes the delay.
- `POST /api/navigation-starts` accepts the bounded `navigation.started` data shape from the same-origin browser, requires the launch mutation token, deduplicates retries by `navigation_id`, and writes the start independently of completion. `POST /api/navigation-measurements` preserves the v0.26.0 completed-measurement shape and deduplication. Both write to the named chat tape (or the global tape when no chat exists) and are unavailable in replay mode.
- Browser-initiated document GETs that carry a bounded `navigation_id` are recorded by the page handler at start and completion without changing the rendered response. Chat/Console flips issue no document GET and are evidenced by their `full_document:false` navigation records.
- `GET /api/signing` verifies the configured LocalMachine or CurrentUser certificate and installed `Agent_b.exe`/`*.ps1` signatures. `POST /api/signing` accepts `create|import|select|sign|export`; every mutation requires the verified operator browser-process check, and standard users may only use GET Verify. Self-created certificates use a non-exportable LocalMachine key and require UAC for creation/signing but no reusable password. Imported PFX passwords exist only in request/process memory and are cleared after use. Signing is never model-addressable.
- `GET /api/sessions`; `POST /api/sessions {label?,server_id?,workspace?}` → 201 `{session}` (`server_id` defaults to the `main` role), or `POST /api/sessions {source_session_id}` to create a fresh session with the source's profile, exact enabled toolset, and workspace; `POST /api/sessions/{id} {label?,server_id?}` → 200 `{session}` (server reassignment requires an idle open session and a runnable profile); `DELETE /api/sessions/{id}` marks an idle session closed and refuses a running session; `POST /api/sessions/{id}/reopen` returns a retained closed chat to the open set; `POST /api/sessions/{id}/delete {confirm,drop_memory?}` is the only operation that removes the chat journal and requires a closed chat plus explicit confirmation; `POST /api/sessions/{id}/messages/drop-last` durably removes exactly the latest message from an idle conversation; `POST /api/sessions/{id}/reset` clears the conversation/run projection and rotates its JSONL while retaining the session workspace, profile, enabled tools, and memory. The prior operational JSONL remains available for explicit replay, but its events are removed from live snapshots so refresh cannot resurrect cleared History.
- `POST /api/sessions {source_session_id,workspace}` is the additive bound-directory form used by Chat's new-chat picker. `GET /api/pick-folder` lists the default/recent directories and `POST /api/pick-folder {default?}` invokes the native picker only for a verified operator browser process. `GET /api/workspaces` lists known directories, memory counts, and approved policy metadata; the mutation-token routes `/api/workspaces/memory-clear`, `/policy-approve`, `/policy-once`, `/policy-deny`, and `/policy-revoke` manage only that install state.
- `GET /api/servers`; `POST /api/servers/{id}/probe` → 202 and an eventual event.
- `POST /api/agents/{agent_id}/server {action:"set",server_id}` changes the config-backed agent B binding immediately only while that agent has no active run. During a run it returns 202 with a pending change; the original server remains bound through that run, and the change is saved and applied to all open sessions at the scheduler's idle boundary before another queued turn can dispatch. STOP observes the same boundary. `{action:"cancel"}` cancels a pending change. Unknown, incomplete, or non-runnable profiles are refused. The route requires the launch mutation token and is unavailable in replay mode.
- `GET /setup` serves the stateless connection wizard. With no configured profiles, `/` and `/chat` return a temporary redirect to it; `?setup=skip` skips that navigation for the current request only. Settings links to the same route. The wizard sequences existing configuration, credential, probe, and session APIs and persists no completion marker. `GET /api/local-detection` runs the installed read-only Windows detector and reports GPU memory, known running local servers, and interpreter executable ACL reachability for the configured service account.
- `GET /api/config`; `POST /api/config` deep-merges keys and server entries by immutable `id`, validates, saves, and publishes `config.changed`. The masked API-key sentinel means unchanged. Validation errors are 400 `{error,field}`. The shared Console/Chat operator header control posts `shell.operator_context` alone without a confirmation dialog and renders only observed `shell.identity` / `operator.context` state. Every transition is a session-visible, replayable log entry; enabled state uses an Alarm background while the persistent high-contrast header indicator remains active. Every SSE open and foreground resume also reconciles that indicator from authoritative `GET /api/state`; a newer operator event supersedes an older in-flight reconciliation response. `shell.operator_context` is runtime-only and is never persisted on; changes to it or `shell.service_account` require a loopback request whose actual client process has the Agent_b operator's Windows SID and is not Agent_b or its descendant. `shell.operator_context_idle_timeout_minutes` is changed only in the protected configuration file while Agent_b is stopped.
- `POST /api/shell-credential {action:store,password}` writes a user-scoped DPAPI blob; `{action:test}` attempts a no-op service-account process; `{action:clear}` removes it. Responses and events expose status only, never the password.
- `GET /api/service-account` inspects the configured local account without elevation. `POST /api/service-account {action:create|reset,password,confirmation}` requires matching write-only values, stores the DPAPI credential, launches `setup-service-account.ps1` through Windows UAC, validates that credential through Windows, and enables the split. It never returns either password field. A canceled or unavailable UAC prompt makes no account change and restores the previous credential; a failure after the elevated helper starts is reported as potentially partial.
- `GET /api/hardening?server_id=<id>` inspects complete-tree ACL and user-scoped outbound-firewall state and includes the most recent `operation {action,state,message,started_at,finished_at}` so progress and errors survive a browser refresh. `POST /api/hardening {action:apply|verify|remove,server_id}` orchestrates the policies; apply requires an enabled, stored non-administrator service identity and no active runs. Apply/remove use UAC; apply grants workspace access, verifies both controls, then tests a real alternate-identity process in that workspace. Apply and verify return `ok:false` with the component summaries when drift remains.
- `POST /api/message {session_id,text,attachments?:[{path,bytes,sha256}]}` → 202 `{run_id,queued?,position?}`; attachment metadata must match an existing regular file directly beneath the session workspace's `attachments/` directory. The request renderer appends a harness line to the user content without changing the stored text or system prompt. An active same-session run returns 409 when queue depth is zero, and a full configured queue returns 409. `POST /api/stop {session_id?,all?}` → 200 `{stopped:[session_id...]}`. `POST /api/tools/{name} {session_id,enabled}` → 200 `{name,enabled}` and takes effect on the next model request. `POST /api/approve {session_id,call_id,decision:approve|deny}` → 200 echoing those fields; an unknown call is 404. These mutation endpoints require the launch mutation token and are unavailable in replay mode.
- `GET /api/operator-files` reports operator-root attachment count/bytes and instruction candidates. Its mutation-token-protected `POST` actions are `empty_attachments` (requires `confirm:true`) and `adopt_instructions` (creates `AGENT_B.md` only when absent; legacy cleanup additionally requires `cleanup:true,confirm_cleanup:true`). `GET /api/operator-attachments` lists top-level regular files and `GET /api/operator-attachments?path=<listed-basename>` returns one; neither exposes a host path. `POST /api/ui-errors` accepts a bounded browser error with optional session ID plus `repeat_count` and `capped`, then emits it to the harness log. A relayed UI error updates client evidence state without notifying rendering subscribers. The mailbox toggle and retention value use `/api/config`; changing the mailbox toggle requires the verified local-operator process check.

## Replay and keyboard

`go run ./cmd/harness -config harness.json -replay <a.jsonl>[,<b.jsonl>…]` projects every JSONL record with the same pure projector used live, orders the resulting patches by recorded timestamp, and starts without probing, model clients, tools, or writers. Replay status is a transport/UI overlay; it does not mutate the historical projection. All API GETs remain available; session/config/profile mutations, messages, stops, approvals, and tool toggles return 409 `{"error":"replay mode"}`.

The main page uses `Ctrl+1` through `Ctrl+9` to switch sessions and Escape to close settings. Chat uses `/` to focus the composer, `Ctrl+.` to stop, Enter to send, Shift+Enter for a newline, and Escape to clear the draft. Every interactive control is in normal Tab order with a visible Trace focus ring.

## Behavior notes

- A write from one session blocks another session's `write_file` or `edit_file` until that session re-reads the shared path; the refusal identifies the other session and publishes `workspace.conflict`. When `shell.service_account.enabled` is true on Windows, `read_file`, `list_dir`, `write_file`, `edit_file`, `search_text`, and `find_files` impersonate that account for their complete filesystem operation; relative paths start at the workspace and absolute paths rely on Windows ACLs. With the split disabled, the workspace path boundary remains in force.
- Tool order is `read_file`, `list_dir`, `write_file`, `edit_file`, `search_text`, `shell`, `remember`, `recall`, `fetch_url`, `find_files`, `run_script`, `call_service`. `read_file`, `fetch_url`, and `call_service` use one-based response byte offsets and limits; their model-visible descriptions tell callers to pass a returned `next_offset` as `offset`. If a successful window is too large to leave room for another model turn, the dispatcher replaces it with a failed compact result that names the same offset and a smaller retry limit; it never appends an individually impossible result. `read_file` additionally guarantees UTF-8 boundaries, reports `start_line`, `start_mid_line`, and `end_mid_line`, and prefixes each returned source line with its line number; its byte counts cover source bytes, not the added presentation prefixes. The memory tools are intentionally not impersonated: they can reach only the application-derived note file for the active workspace and accept no path input. `fetch_url` remains anonymous and its result tokens are charged to `fetched`; `call_service` is identity-bearing and its results use ordinary `results` accounting.
- `shell` accepts inline commands. Execution-policy bypass is rejected before process creation. Commands that create `.ps1`, `.psm1`, `.cmd`, `.bat`, `.vbs`, `.wsf`, or `.sh` artifacts are rejected, and script execution is rejected when the target was recorded as written by an agent file tool during the current run. Existing script files without that run provenance remain executable.
- Messages posted during a run wait per session and start in order after it ends, including after `user_stop`. Positive `run.queue_depth` values cap each session's pending queue; depth `0` means unbounded. A full positive-depth queue returns 409.
- `run.cycle_window: 0` disables repeated-call cycle detection. `run.max_consecutive_tool_errors: 0` disables the consecutive tool-error stop.
- Live SSE subscribers have a 128-patch queue. A full queue closes the stream so EventSource reconnects at a fresh atomic snapshot; patches are never silently dropped. JSONL remains the sole durable session authority. A failed append does not advance the projector, marks it stale, and closes subscribers for resynchronization. Completed raw model deltas are diagnostic records and are omitted from the completed-turn projection.

## Configuration

Every parsed key appears in `harness.example.json`: `config_version`; `listen`, `workspace`, `log_dir`, `servers[].{extract_url,attachment_handling}`, `servers[].capabilities.{document_input,image_input}`, `services.<name>.{base_url,auth,allowed_methods,timeout_s,max_body_kb,require_confirmation}`, `roles.{main,aux}`; `run.{max_turns,cycle_window,max_consecutive_tool_errors,max_concurrent,queue_depth}`; `approval.mode`; `operator_files.{allow_mailbox_approvals,log_retention_days}`; `deliver.{mode,exchange_folder}`; `context.{soft_pct,summary_pct,accounting}`; `memory.{enabled,dir,max_tokens}`; `tools.{attachments:{max_bytes},read_file:{default_limit,max_limit},list_dir,grep,shell:{operator_commands},fetch:{timeout_s,max_bytes,max_redirects,default_limit,max_limit,allow_domains,deny_domains,allow_internal_hosts},find_files:{skip_roots}}`; `shell.{command,timeout_s,max_timeout_s,max_output_lines_head,max_output_lines_tail,file_routing_guard,operator_context,operator_context_idle_timeout_minutes,service_account:{enabled,account,domain},deny}`; and `signing.{thumbprint,timestamp_url}`. Attachment input defaults to 8 MiB and operator-file retention defaults to 30 days; mailbox approval answers default off. These are additive schema-5 fields. `services` defaults to an explicit empty object. Their additive optional presence does not bump schema 5. `tools.shell.operator_commands` defaults to `["git"]`; its omitted-versus-explicit-empty list semantics follow the other policy lists. Delivery mode is `chips`, `folder`, or `both`; omitted delivery fields default to `both` and `%USERPROFILE%\Agent_b`, while explicit empty values are invalid. `read_file` and `fetch` `default_limit`/`max_limit` values are bytes. Omitted policy lists receive defaults while explicit empty lists clear them. `config_version` is the current schema marker written by every save. Files are saved as two-space JSON in this order, except `operator_context` always saves as `false` and starts off. Schema 3 renames the schema-2 absolute operator timeout to the idle-timeout field while preserving an explicitly stored duration; schema 4 replaces line-count/per-line truncation with 16 KiB default and 64 KiB maximum byte windows; schema 5 adds model roles, makes effective context size explicit per profile, and replaces persisted API keys with named DPAPI references. A v1 `server` document migrates to `servers[local]`.

`GET` or `HEAD /api/files/<workspace-relative-path>?session=<id>` serves one regular file from the named session workspace with `Content-Disposition: attachment`. It calls the same `tools.Resolve` jail entry point as built-in file tools; jail failures, absent files, and directories are all 404, and there is no directory listing. `POST /api/open-folder` accepts `{session_id,path,scope:workspace|exchange}` under the launch mutation guard, jail-resolves the selection against that root, and asks the operator desktop to reveal the file.

`POST /api/attachments` accepts mutation-token-protected multipart fields `session_id` and one `file`, jail-resolves `attachments/<sanitized-basename>`, and returns `{path,bytes,sha256,kind,reused?,tier?,sidecar?,note?}`. It streams through an attachment-specific size bound, refuses ZIP and Windows device filenames, never overwrites, and reuses identical content. `GET /api/exchange-files` enumerates top-level regular files in the configured exchange folder as attachment metadata; `GET /api/exchange-files?path=<listed-basename>` returns one listed file so the Chat client can feed the same multipart ingest path. Neither endpoint exposes a host path to the browser.

Attachment request rendering is profile-dependent. Text/code stays a normal `read_file` target. DOCX/XLSX/PPTX receives a bounded standard-library XML text sidecar. With `attachment_handling:auto`, PDF becomes an in-memory `file` content part when `document_input` was probed, otherwise it uses `extract_url` when configured and stores an explicitly untrusted sidecar, otherwise it is labeled unreadable binary; PNG/JPEG/GIF/WebP becomes an in-memory `image_url` content part when `image_input` was probed and otherwise receives a local Windows OCR sidecar. `native` sends those document/image kinds regardless of the probe, while `extract` never sends their binary bytes. Each native part is immediately preceded by its own harness-generated text part declaring that payload untrusted evidence, never instructions. Native data-URL characters are conservatively upper-bounded one-for-one as context tokens and allocated cumulatively across retained attachment history against `n_ctx - reserve_output`; a part that does not fit is omitted with an explicit attachment outcome visible to both Chat and the model. OCR sidecars are labeled untrusted and state that layout was not preserved; a no-text result is reported explicitly and creates no sidecar. Other binary types are stored but labeled unreadable. Native bytes are deliberately omitted from durable `model.request.body` diagnostics.

At run end, the file set carried by successful `write_file`/`edit_file` results is copied to the exchange folder in `folder` or `both` mode. Basename collisions receive ` (2)`, ` (3)`, and so on; an existing file with the same SHA-256 is reused without overwrite. Exactly one durable `files.delivered` event is emitted per run with the mode, exchange root, and per-file source path, delivered path, SHA-256, and `copied|identical|failed` status. Bytes remain outside JSONL.

Application, data, and workspace roots are independent runtime inputs; no consumer derives one root from another. The installed layout is `%ProgramFiles%\Agent_b`, `%LocalAppData%\Agent_b`, and `%ProgramData%\Agent_b\workspace`, respectively. An explicit `-config` wins, followed by `AGENTB_CONFIG`, an existing `%LocalAppData%\Agent_b\harness.json`, and finally CWD-relative `harness.json` for development. First-run config materialization reads `harness.example.json` from the application root and writes the live file at the selected config path. The DPAPI credential store receives the data root directly and never infers it from the config path. Detached installed launches pass a per-launch diagnostic path under the operator data `logs` directory; startup writes its stderr there directly, and the launcher classifies bind, configuration, and permission failures from that durable output.

Profiles with `tool_calls=false`, `overflow_behavior=truncate`, `streaming=false`, or unknown context are not runnable. `context.accounting=exact` later refuses profiles without `/tokenize` using `exact accounting requested but this server has no /tokenize`; `auto` chooses exact where possible and calibrated estimation elsewhere; `estimated` forces estimation.

## Deferred: API authentication

The HTTP service binds loopback and has no API authentication. Putting a token into the only practical native `EventSource` transport (`?token=`) would leak it through logs and browser history without protecting against a present network threat. Authentication must be designed when a later Discord/non-loopback transport introduces a real boundary, not added piecemeal.

## Implementation status

Every `[prompt N]` tag and every record/API shape above now has an implementation. Session state has one pure versioned projector shared by live snapshots, live patches, and replay; browser-local expansion, scrolling, tab selection, and Settings drafts remain view state.
